Verificación de Cumplimiento PCI-DSS v4.0

Entregable obligatorio [SEC-3] — Comprobación de que la base de datos no contiene datos de tarjeta (PAN/CVV)

¿Qué verifica esta auditoría?

El estándar PCI-DSS penaliza con pérdida de hasta 4 puntos el almacenamiento de números de tarjeta (PAN), CVV o fecha de expiración. En Bistró Gourmet, la tabla pagos en pagos_db contiene exclusivamente el payment_intent_id de Stripe — nunca datos bancarios reales.

Verificación de Docker Hardening (SEC-5)

Aislamiento de red interna y protección de puertos de bases de datos

1. Puertos No Expuestos

mariadb-master, mariadb-slave, mariadb-audit y redis no tienen directivas ports: en docker-compose.yml. No responden a escaneos externos en 0.0.0.0:3306 ni 0.0.0.0:6379.

2. Usuario No-Root

Todos los microservicios PHP se ejecutan bajo la cuenta sin privilegios USER www-data en sus respectivos Dockerfiles. El usuario de MariaDB app_user tiene permisos mínimos necesarios.

3. Volúmenes Separados

La base de datos de auditoría se encuentra en el volumen independiente technova_audit_db_data, aislado de las bases de negocio (technova_master_db_data / slave_db_data).

4. Resource Limits

Cada contenedor tiene directivas cpus y memory configuradas para prevenir saturación por ataques DoS/DDoS.

5. Red Interna Privada

Red technova_network (tipo bridge interno). Los microservicios se comunican por nombre de contenedor. Solo el Gateway Nginx expone los puertos 80/443.

6. Healthchecks Automáticos

Cada servicio tiene un healthcheck en Docker Compose para garantizar disponibilidad y reiniciar automáticamente en caso de fallo.
